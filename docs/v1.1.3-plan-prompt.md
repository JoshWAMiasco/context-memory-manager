# CMM v1.1.3 — Plan (not implemented yet)

Planning document for the requests in `docs/v1.1.3_feature.md`. Nothing here is built. Read it, settle the
**Open decisions** at the end, then hand it to a Claude Code session in the `context-memory-manager` repo as the
implementation prompt.

**Goal:** more file types can be viewed (Office documents, video thumbnails), and moving working files between
the user's computer and a CMM server on Ubuntu is easy: download, re-import / replace, see what changed, and drag
a path into the terminal. Plus a light theme next to today's dark one.

## Context

- **Repo:** `~/Documents/GitHub/context_memory_manager`, version `1.1.2` → `1.1.3`.
- **Stack:** Next.js 16 server plus Electron for the desktop app, React 19 / TypeScript, Drizzle + better-sqlite3,
  pdf.js, CodeMirror 6 (`@codemirror/merge` for diffs), xterm.js + node-pty, simple-git, archiver.
- **Ground rules from the 1.1.2 work. They still apply:**
  - Every API route goes through `withApi` (`server/auth/guard.ts`): session, lock, role, `storageAccess`,
    step-up.
  - Every path is resolved through the path jail (`resolveInStorage` in `server/security/path-jail.ts`).
  - File content goes through the storage pipeline (`runGuards` / `collectTransforms` in
    `server/storage/pipeline.ts`), so protection, encryption and the versioning autocommit hook keep working.
  - **Offline:** the server never contacts the internet, and `npm run check:offline` must pass. No CDN, no
    telemetry, and the installer never runs `apt`. Any new dependency is bundled and lazy-loaded.
  - **CSP** (`proxy.ts`): `default-src 'self'`, `img-src 'self' blob: data:`, `connect-src 'self'`,
    `object-src 'none'`, and no frames. Any feature that needs this loosened is called out below.
  - Run lint, typecheck, Vitest and the e2e suites for each part. Add tests for new logic.

## Part 1 — View Office documents (xlsx, docx; pptx later)

### Your question: is there an SDK or service for Ubuntu, with a Microsoft 365 sign-in?

There are three kinds of option:

| Option | Runs where | Fidelity | Fit with CMM |
|---|---|---|---|
| **A. Microsoft 365 / Graph API.** The user signs in with Entra ID (OAuth). CMM uploads the file to the user's OneDrive and embeds Graph's `driveItem/preview` URL. | Microsoft's cloud | Excellent | **Poor.** It needs internet, an Entra app registration, and CSP `frame-src`/`connect-src` for Microsoft hosts. It also copies private (even encrypted-folder) files to OneDrive just to show them. It breaks the offline promise in the Server Guide and `check:offline`. Office Online Server (the on-premises version) runs on Windows Server only, not Ubuntu. |
| **B. Self-hosted office suite on Ubuntu:** Collabora Online (CODE) or ONLYOFFICE Docs Community, talking WOPI. | Same Ubuntu server, usually in Docker | Excellent, and can edit | Possible later. Offline-capable, but heavy (≈1–2 GB, a separate service, AGPL), needs a WOPI host implemented in CMM, and needs an iframe (CSP change). It's a release of its own. |
| **C. Render in the browser with bundled JS libraries.** Optionally, LibreOffice headless on the server converts to PDF. | Inside CMM | Good for xlsx/docx. Weak for pptx without LibreOffice. | **Best fit.** No sign-in, no internet, no new service. Works the same on the desktop app and the server. |

**Decided:** build **C, with LibreOffice support**, in 1.1.3. The **bundled JS libraries render xlsx and docx**
in the browser. **LibreOffice → PDF** on the server handles **every other Office format** (pptx, legacy
doc/xls/ppt, OpenDocument). A (Microsoft 365) is out. B stays a
possible 1.2+ item if editing Office files in CMM becomes a goal.

PDF already works (`components/viewer/pdf-viewer.tsx`, pdf.js). Nothing to do there.

### What already exists
- `lib/file-kinds.ts` decides the kind from the extension. `components/viewer/file-view.tsx` `planView()` picks a
  viewer. Unknown kinds fall to `PlaceholderViewer`.
- `/api/fs/raw` streams the file (decrypted if it's in an unlocked encrypted folder) with a sandbox CSP.
- `components/viewer/csv-table.tsx` is a virtualized table. `lib/workers/csv-parse.worker.ts` shows the pattern
  for parsing in a Web Worker.

### Work
1. **File kinds.** Add `spreadsheet` (`xlsx`, `xlsm`; `xls`/`ods` only if the library reads them) and `document`
   (`docx`; `odt` optional) to `FileKind` and `MEDIA_TYPES`, with their real MIME types. Add `presentation`
   (`pptx`) as a kind that shows the placeholder until step 5 lands. Update `KIND_LABELS` and the icons.
2. **Spreadsheet viewer** (`components/viewer/spreadsheet-viewer.tsx`):
   - Fetch the bytes from `/api/fs/raw`. Parse in a **Web Worker** (new `lib/workers/xlsx-parse.worker.ts`).
   - Sheet tabs. Each sheet renders in the existing virtualized `csv-table.tsx`, reused, not copied. Show
     computed values (cached results; no formula evaluation), with a toggle to show formulas if the library
     exposes them.
   - Limits like CSV: reuse `ViewerLimits.csvMaxRows`, plus a byte cap (e.g. 25 MB). Above it, the placeholder
     with Download.
   - **Library:** `exceljs` (MIT; use its browser build, lazy-loaded). Do **not** use the npm `xlsx` package:
     npm only has 0.18.5, which has known advisories. SheetJS now ships only from its own CDN, which doesn't
     fit an offline, lockfile-pinned build. Check `read-excel-file` (MIT, smaller) as a lighter alternative.
     Pick one after `npm audit` and a bundle-size check.
3. **Document viewer** (`components/viewer/document-viewer.tsx`):
   - **Library:** `docx-preview` (Apache-2.0, keeps page layout, tables and images) or `mammoth` (BSD-2,
     semantic HTML, simpler). Recommend `docx-preview` for "looks like Word"; keep `mammoth` as the fallback
     if output sanitization becomes hard.
   - **Security:** a docx is untrusted input rendered into CMM's own origin. Render into an isolated container.
     Strip `script`, `iframe`, `object`, `on*` attributes, and `javascript:`/`data:` links (except `data:image/*`).
     Make every hyperlink go through the existing external-link confirmation (`isExternalLink`). No remote
     images (CSP already blocks them; check that nothing logs CSP errors in a loop). Add a test that a
     malicious docx with a `javascript:` link and an embedded script renders inert.
   - Byte cap (e.g. 25 MB) and a cancel button, using the `ContentLoader` the other viewers use.
4. **Encrypted folders:** both viewers read through `/api/fs/raw`, so decryption and the unlock panel work as
   they do for PDFs. Nothing parsed is written to disk.
5. **LibreOffice → PDF on the server (approved)** for the formats the JS viewers don't cover: `pptx`, legacy
   `doc`/`xls`/`ppt`, `odt`/`ods`/`odp`. xlsx and docx always use the JS viewers, not LibreOffice. Without LibreOffice
   installed, those files show the placeholder with Download and a short "Install LibreOffice on the server to
   preview this" hint (admins see the install help).
   - Detect `soffice` the way `server/versioning/git-detect.ts` detects git, and reuse the "install help" dialog
     pattern (`components/versioning/git-install-help.tsx`). The installer stays apt-free. The admin installs
     `libreoffice-core` + writer/calc/impress (or `libreoffice-nogui`) themselves.
   - Convert in a background job (`server/jobs/*`). Use `soffice --headless --convert-to pdf` with its own
     `-env:UserInstallation` profile, macros disabled, a timeout, and a memory cap. Cache the PDF under
     `.cmm-tmp/previews/<hash-of-path+etag>.pdf`. Show it in the existing `PdfViewer`.
   - **Refuse conversion for files in encrypted folders** (or convert in tmpfs and delete right away). A cached
     plaintext PDF next to encrypted data would defeat the encryption.

### Acceptance
- Opening an `.xlsx` shows its sheets as tables with tabs. A large one shows the placeholder with Download.
- Opening a `.docx` shows formatted text, tables and images. Links ask before leaving CMM. A crafted docx can't
  run script.
- Both work in an unlocked encrypted folder, and show the unlock panel in a locked one.
- With LibreOffice installed, a `.pptx` (and `.doc`/`.xls`/`.ppt`) opens as a PDF in the existing PDF viewer.
  The second open of the same unchanged file is instant (cache). Without LibreOffice, the placeholder explains
  why.
- A file in an encrypted folder is never left as a plaintext PDF on disk.
- No network requests (`check:offline` passes). No new CSP sources.

## Part 2 — Video: thumbnail preview only

### What already exists
`PlaceholderViewer` explicitly never plays media ("no `<video>`, `<audio>`…"). `/api/fs/raw` already serves
video with range requests and decrypts on the fly.

### Approach
**Recommend: generate the thumbnail in the browser.** No server dependency.
- A hidden, muted `<video preload="metadata">` is created off-DOM with its `src` set to the raw URL. Wait for
  `loadedmetadata`, seek to `min(1 s, 10 % of the duration)`, and on `seeked` draw the frame to a `<canvas>`.
  `toBlob()` gives the image, shown as `<img src="blob:…">` (already allowed by `img-src blob:`). Then release
  the video element (`removeAttribute("src")`, `load()`) so it stops fetching.
- Show the thumbnail at the top of the placeholder, plus **duration and resolution** in the metadata list. Keep
  Download. No play button, no controls, no audio.
- If the codec can't be decoded (e.g. HEVC in some browsers, or `mkv`/`avi`), show today's placeholder text. Use
  a timeout of about 8 s.
- Keep thumbnails in memory per `path+etag` for the session. Don't write them to disk (that matters for
  encrypted folders).
- Rewrite the `PlaceholderViewer` doc comment: the media element is now used only to capture one frame.

**Alternative, if needed later:** `ffmpeg` on the server for codecs browsers can't read. Same pattern as
LibreOffice: optional, detected, never installed by CMM. Not in 1.1.3.

### Acceptance
- An `.mp4`/`.webm`/`.mov` shows a still frame, duration and size, plus Download. Nothing plays or makes sound.
- Unsupported video shows the old placeholder after the timeout, with no console error loop.
- Works for video in an unlocked encrypted folder.
- Tree rows stay icons. There's no grid view to put thumbnails in. Thumbnails in a grid view would be a
  separate feature.

## Part 3 — Import / export working files over the web interface

### What already exists (more than it seems)
- **Download:** `GET /api/fs/download` sends a file as an attachment, or **a folder as a streamed zip**
  (`server/storage/zip-download.ts`). It skips `.cmm`, `.cmm-trash`, `.cmm-tmp` and `.git`, skips symlinks, and
  decrypts. The context menu already has "Download" / "Download as zip". Step-up `download` applies.
- **Upload:** chunked and resumable (`server/storage/upload.ts`, 8 MB chunks). It checks free space up front,
  replaces files atomically with `overwrite`, and encrypts as it arrives in an encrypted folder. The client
  queue (`lib/client/upload-queue.ts`) already asks **Replace / Keep both / Skip (apply to all)** when a name
  exists.
- **Versioning:** the autocommit hook (`server/versioning/autocommit.ts`) commits app writes. Diffs exist:
  `GET /api/versioning/diff`, `components/versioning/diff-view.tsx` (split/unified), and `history-panel.tsx`.

So the gaps are: **folder upload, multi-item download, an explicit Replace action, and a "what changed"
page.**

### 3a. Download: fill the gaps
1. **Several selected items → one zip.** Today the menu downloads one entry. Add a multi-path download: a new
   `paths` parameter (or a POST that returns a one-time token, to avoid long URLs) that zips the selection.
   Reuse `createFolderZipStream`, generalized to take several roots. Use one step-up for the batch.
2. **Encrypted content in a zip:** the zip contains decrypted files. Make sure the existing
   `components/encryption/encrypted-download-dialog.tsx` warning also appears for folder and multi-item zips
   that contain encrypted files, not only single files.
3. **Progress:** a streamed zip has no `Content-Length`, so the browser shows no total. Add a pre-count
   (files and bytes, using the existing walk) to the confirmation ("About 1.2 GB in 3,410 files").
   Optional: an `x-cmm-estimated-size` header.
4. Check that the zip streams through Caddy (`deploy/linux/Caddyfile.example`) without buffering or timeouts on
   multi-GB folders. Update the Server Guide if it needs `flush_interval -1` or longer timeouts.

### 3b. Upload folders (re-import a working folder)
Today folders are skipped ("Folders were skipped", `readDroppedFiles` in `file-tree.tsx`).
1. On drop, walk `DataTransferItem.webkitGetAsEntry()` recursively. Also add an **Upload folder…** item using
   `<input type="file" webkitdirectory>`.
2. Create the folders through `/api/fs/mkdir`, then queue the files with their relative directories in the
   existing upload queue. Collisions use the existing Replace / Keep both / Skip prompt, with "apply to all".
3. Skip OS junk (`.DS_Store`, `Thumbs.db`, `desktop.ini`) and anything under `.git/` unless the user opts in.
   Show the count of skipped items.
4. **Step-up:** today `upload` step-up is asked **per file** in `/api/fs/upload/init`. On a server reached from
   another network, every protected action asks, so a 500-file folder would prompt 500 times. Add a batch grant
   (approved):
   one step-up for `storageId:<dir>/**` that is valid for that batch and a short time. Check how
   `server/auth/guard.ts` matches step-up resources before designing it. This is a security change and needs
   tests for scope (it can't be used outside `<dir>`) and expiry.

### 3c. Replace a file from the computer (right-click → Replace…)
1. Add **Replace with file from computer…** to `explorer-context-menu.tsx` and the file pane's More menu, for a
   single file. Disable it with the existing reasons (read-only, protected, locked encrypted folder, unsaved
   edits open in the editor).
2. It opens a file picker. The chosen local file may have a different name; the **target keeps its name**. If
   the extensions differ (e.g. `.docx` over `.xlsx`), ask first.
3. Upload through the existing path with `overwrite: true` and the target's name, plus a new optional
   **`expectedEtag`**. `initUpload` and `complete` return `409 CONFLICT` if the file changed since the menu
   opened, so another user's or the agent's edit isn't overwritten silently.
4. If the folder is versioned: call `flushAutocommits` **before** writing, so pending edits get their own commit.
   Then commit the replace with a recognizable message (`Replace: <name> (uploaded)`). Add a `replace` kind to
   `classifyCommit` in `server/versioning/history.ts`.
5. If the folder is **not** versioned: before the atomic swap, the old file goes to **CMM Trash** (existing
   trash, restorable) so a "before" exists. (Decided.)
6. Afterwards, a toast: "Replaced *name*". For a **text file**, it adds **See what changed**, linking to 3d.
   Office and other binary files get no compare link (see 3d).
7. If a text file is open in the editor, the existing external-change banner fires (Reload / Keep mine /
   Compare). Check that it does.

### 3d. "What changed" page (git comparison)
- A new route, e.g. `app/(app)/storage/[storageId]/changes/[[...path]]/page.tsx`. On the left, the commit list
  for the folder or file (reuse `readLog`, filterable by kind: uploads/replaces, edits, external, restores). In
  the middle, the files changed in the selected commit (`readCommitFiles`). On the right, `DiffView`
  (split/unified) for the selected file. Add "Restore this version" through the existing `restore-file` route.
- `history-panel.tsx` stays the quick side panel and gets an "Open full page" link.
- Not versioned: compare the current file with its copy in Trash (from 3c.5), using the existing
  `components/editor/compare-view.tsx`. Then offer "Turn on versioning to keep every version" (reuse
  `git-required-dialog.tsx` when git is missing on the server).
- **Text files only (decided).** Compare and diff are for text content: Markdown, JSON, code, plain text, CSV
  (everything `isTextKind` in `lib/file-kinds.ts` covers). For Office documents and other binary files, the page
  says "Comparing this file type isn't supported yet" instead of a diff. Restoring an older version through the
  existing history keeps working, since git still stores the file. Don't add any Office-specific diff or
  rendering of old versions in 1.1.3.
- **Future improvement (not 1.1.3):** content compare for Office files (xlsx cell changes such as
  `Budget!C7: 1,200 → 1,350`, docx/pptx text diff), reusing the Part 1 parsers and LibreOffice.

### Acceptance (Part 3)
- Selecting several items and choosing Download gets one zip. A folder zip of an encrypted folder warns first.
- Dropping a folder from the computer recreates it, with progress and a collision prompt, and asks for step-up
  at most once.
- Right-click → Replace… swaps the file atomically, keeps its name, refuses if the file changed meanwhile, and
  commits (versioned) or trashes the old copy (unversioned).
- "See what changed" opens the page at that change, and text files show a line diff. Office and binary files show
  "not supported yet" instead of a diff. Restore works for both.

## Part 4 — Drag a file or folder onto the terminal to paste its full path

### What already exists
- Tree rows set `application/x-cmm-entries` (`{ storageId, paths }`) on drag (`components/explorer/file-tree.tsx`).
- `components/terminal/terminal-view.tsx` hosts xterm.js. It has no drop handling.
- `GET /api/fs/abs-path` is **desktop-only on purpose** ("a server never tells browsers where its files live").
- Terminals are **admin-only and off by default on servers** (`server/terminal/index.ts`, `terminal.enabled`).

### Work
1. **Drop target:** handle `dragover`/`drop` on the terminal container, with an overlay "Drop to paste path".
   Accept CMM entries (and OS files, see 3).
2. **CMM entries → absolute paths.** Add `POST /api/terminals/[id]/paths` with `{ storageId, paths[] }`. It
   checks the terminal belongs to the caller and that terminals are available to them (same check as opening
   one). It jails each path, applies the storage-access check, and returns the absolute paths. This keeps the
   "no paths to browsers" rule for everyone except an admin who already has a shell on that machine. Don't
   loosen `abs-path` itself.
3. **Files from the computer:**
   - **Desktop app:** add `getPathForFile(file)` to the bridge (`lib/desktop-bridge.ts`, `electron/preload.ts`,
     using Electron's `webUtils.getPathForFile`). The terminal is a local shell, so the local path is right.
     Validate it with `isBridgePath`.
   - **Server in a browser:** the browser can't reveal a local path, and the path wouldn't exist on the server
     anyway. Show a toast: "Files from your computer have no path on the server. Drop them on the file pane to
     upload." (Decided: explain only; no upload-and-paste.)
4. **Quoting:** POSIX shells get single quotes (`'` → `'\''`), and multiple paths are joined with spaces.
   Windows desktop (PowerShell / cmd) quotes for the shell node-pty started. Names with newlines or control
   characters are refused with a toast. Insert with xterm's `terminal.paste()` (respects bracketed paste) and
   **never send Enter**.
5. Unit tests for the quoting (spaces, quotes, `$`, unicode, newline refusal). A socket/route test that a
   non-owner and a non-admin are refused. An e2e test: drag a tree row onto the terminal and check the
   terminal's input line.

### Acceptance
- Dragging one or more tree items onto an open terminal types their quoted absolute paths at the cursor, without
  running anything.
- On the desktop app, dragging a file from Finder/Explorer pastes its local path.
- On a server in a browser, an OS file drop explains why there's no path. No server path leaks to anyone who
  can't open a terminal.

## Part 5 — Light mode (today's theme becomes Dark)

### What already exists
- **All colours are tokens.** `styles/design-tokens.css` defines every colour, shadow and decoration value as a CSS
  variable in Tailwind v4's `@theme static`, and the components use `bg-surface`, `text-foreground-muted`,
  `border-line` and so on. Because the variables are emitted, a second set of values under a selector switches
  the whole UI without touching the components.
- **Dark is hard-wired in a few places:** `app/layout.tsx` puts `dark` on `<html>`; `styles/globals.css` sets
  `color-scheme: dark`; `lib/editor/cmm-theme.ts` says "The app is dark-only"; `electron/main.ts` uses
  `CANVAS_COLOR = "#04101a"` as the window background; `electron/splash.html` has its own colours.
- **The `dark` in `button.tsx`, `badge.tsx`, `static-alert.tsx`, `progress-bar.tsx` and `tooltip.tsx` is a
  variant name** ("the dark fill"), not Tailwind's `dark:` modifier. Leave it; give `--color-dark` a light-mode
  value that still reads as a dark chip.
- **Settings in `server/settings/store.ts` are global and admin-only.** A theme is a personal choice (a server
  has several users), so it can't simply be another setting there.

### Work
1. **Tokens.** Keep the current values as the default (= Dark). Add a light set in `design-tokens.css`:
   ```css
   :root[data-theme="light"] { --color-canvas: …; --color-surface: …; … }
   @media (prefers-color-scheme: light) { :root[data-theme="system"] { /* same values */ } }
   ```
   Define the light values once (one CSS block, or a `@custom-variant`) so they aren't kept twice. Cover every
   colour token, the shadows (lighter, without the navy), and the decoration variables (aurora, scanlines and
   text glow, much fainter or off).
2. **Light palette, designed rather than inverted.** Keep the identity (cyan brand, violet accent, squared
   corners, Oxanium / Martian Mono) on a cool off-white canvas (around `#f4f8fb`) with white surfaces and navy
   text. The status colours that work on navy (`#5ef0b4` success, `#ffd166` warning, `#4cc9f0` brand as text)
   are unreadable on white, so the light set needs darker versions for text and borders. `on-primary` must still
   contrast with the fills. Check every text/background pair against **WCAG AA (4.5:1 body, 3:1 large text and
   UI)**.
3. **Choosing the theme: Light / Dark / System.**
   - **Where:** a quick switch in the account menu (`components/layout-shell/account-menu.tsx`) and an
     "Appearance" row in **Settings › General**.
   - **Default: Dark** (decided), so nothing changes for existing users.
   - **Stored per user (decided):** a new preference on the user (Drizzle migration `0007`, e.g. `users.theme`, or a
     small `user_preferences` table if more personal settings are expected), set through
     `/api/users/me/...`, so it follows the user to any browser.
   - **No flash:** mirror the value in a `cmm_theme` cookie. `app/layout.tsx` reads it on the server and
     renders `<html data-theme="…">`, so the first paint is right. "System" needs no script: the media query
     above handles it. The login, lock and setup pages, where there's no user yet, use the cookie or System.
   - Set `color-scheme` to match (`light`, `dark`, or `light dark` for System), so native scrollbars, form
     controls and date pickers follow.
4. **Places that don't read the tokens, or read them only once:**
   - **Terminal** (`terminal-view.tsx`): `readTerminalTheme()` reads the tokens only when the terminal is
     created, and the ANSI colours are tuned for dark (yellow on white is unreadable). Give the light theme its
     own ANSI palette, and update `terminal.options.theme` on a theme change, without reconnecting.
   - **CodeMirror** (`lib/editor/cmm-theme.ts`): the editor chrome already uses variables. Check the syntax
     highlight colours and the `@codemirror/merge` added/removed backgrounds in light. Set `dark: false` /
     `true` on `EditorView.theme` as appropriate, and remove the "dark-only" comment.
   - **Markdown code blocks** (`styles/markdown.css`, the `.hljs-*` rules) and the Markdown editor.
   - **Hard-coded colours:** `components/icons/cmm-logo-mark.tsx` (the navy tile needs a light variant or a
     border), `bg-loading-puff` (white strokes) and `bg-chevron-white` in the breadcrumb (switch to
     `bg-chevron-black` or `currentColor`) in `styles/background-image-utilities.css`, the default `color` of
     `LoadingIndicator`, the backup topology colours (`lib/backup-topology.ts`, `energy-flow.tsx`), and the
     `decoration-hero-backdrop` gradients in `theme-decorations.css`.
   - **Viewers:** the PDF page background, the CSV table, image transparency checkerboards, and the Part 1
     spreadsheet and document viewers (a docx page is white in both themes; only the surround changes).
   - **The terminal-style "glow" decorations** look odd on white. In light, turn `--decoration-text-glow` and
     `--shadow-glow` down or off.
5. **Desktop app:** set `nativeTheme.themeSource` from the user's choice. `backgroundColor` for new windows and
   the splash follow the theme, or System through `nativeTheme.shouldUseDarkColors`, so there's no dark flash
   before a light page. The renderer tells the main process about changes through a new bridge call in
   `lib/desktop-bridge.ts` / `electron/preload.ts` / `electron/ipc.ts`.
6. **Guides:** light screenshots aren't required. The guides keep the dark ones. Mention the setting in the
   Desktop and Server guides.

### Acceptance
- Light / Dark / System can be picked in the account menu and in Settings. The choice sticks per user across
  browsers and restarts. System follows the OS live.
- A full reload in light mode never flashes dark, including the desktop app's window and splash.
- Every page and dialog is readable in light (explorer, editors, diff and merge views, terminal, backup page,
  settings, login and lock). Text contrast passes AA. An e2e test with `prefers-color-scheme: light` plus
  `data-theme` checks the canvas and key token colours, and takes a screenshot of the main screens.
- Dark looks exactly as it does today (a screenshot comparison of the main screens before and after).

## Part 6 — Dock the terminal beside the editor/viewer

**Goal:** the explorer layout becomes **File tree | Editor/Viewer | Docked terminal**. A terminal can be
**docked** into the right-hand column and **undocked** back to the bottom, chat-like floating panel it is today.
Docked, it can be **minimized to a slim rail**, the same way the file tree hides.

### What already exists
- **Floating dock** (`components/terminal/terminal-dock.tsx`, `terminal-panel.tsx`): chat-window panels pinned
  bottom-right on every signed-in page (mounted in `app/(app)/layout.tsx`). They can be resized, minimized to a
  title bar, and stack into a "+N" overflow. The layout is in `localStorage` under `cmm.terminal-dock`
  (`lib/client/terminals.ts`).
- **Explorer split** (`components/explorer/explorer-workspace.tsx` `SplitView`): `react-resizable-panels`
  `Group` with the tree `Panel` (collapsible to 0, with `ShowTreeRail` and ⌘\) and the file-pane `Panel`. The
  split is saved in `localStorage` (`cmm.split`). Narrow screens use `StackedView` (tree in a drawer).
- **Terminals live on the server.** `TerminalView` reconnects and the server replays the last 256 KB of output
  on every attach, so moving a terminal between places doesn't lose the session.

### Work
1. **Layout (decided):** `[tree] | [editor/viewer] | [terminal]`. The docked terminal is a new collapsible
   `Panel` at the **right end** of the same `Group`, after the file pane. Default width about 35%, min about
   20%, collapsible to 0. Its size goes into the saved `cmm.split` layout. Migrate the old two-panel layout
   value, so the saved layout from 1.1.2 still loads. The column (and its separator) is rendered only while at
   least one terminal is docked; otherwise the layout is exactly today's tree | editor.
2. **Dock / Undock:**
   - A **Dock to the side** button on the floating panel's title bar (`terminal-panel.tsx`), shown on explorer
     pages.
   - An **Undock** button on the docked column's header that sends it back to the bottom, chat-like floating
     dock (today's behaviour, size and position restored).
   - "Open in terminal" opens where the user last put terminals (docked or floating); remember that choice.
   - Store `placement: "floating" | "docked"` per terminal in `TerminalPanelLayout`.
3. **Several docked terminals → tabs** in the docked column's header (title, unread dot, close), with the same
   Restart / Close actions as the floating panel. Floating and docked terminals can coexist.
4. **Minimize like the tree:** the column collapses to a slim vertical rail on the **right edge** (a mirror of
   `ShowTreeRail`), with a terminal icon, an unread dot, and a tooltip with the shortcut. A click or the shortcut brings it back. Add a
   shortcut next to ⌘\ (e.g. **⌘J / Ctrl+J**, the VS Code convention; check it doesn't clash with
   `lib/client/shortcuts.ts` or the editors). Dragging the separator all the way closes it, as the tree's does.
5. **Keep the session when it moves:** re-mounting `TerminalView` reconnects and replays the scrollback.
   Full-screen programs (vim, htop, less) may redraw badly after a replay. Prefer keeping **one xterm instance
   per terminal** in a small client registry, and **moving its DOM element** between the floating panel and the
   docked column, instead of creating a new one. Then send a `resize`, so the shell redraws at the new size.
   Fall back to remount + replay only if moving the element proves fragile.
6. **Pages without the explorer** (dashboard, settings, backup): docked terminals appear in the floating dock,
   minimized, and go back to the column when the user returns to the explorer. Nothing is closed.
7. **Narrow screens (`StackedView`):** no docking. Docked terminals show as floating panels; the Dock button is
   hidden.
8. **Part 4 (drag a path onto the terminal)** must work on the docked terminal too. Dragging a tree row across
   the editor to the terminal column is the main use. The editor/viewer must not treat that drag as a drop
   target on the way. **Part 5 (light mode)** applies to both placements.

### Acceptance
- From a floating terminal, **Dock** puts it in a column to the right of the editor/viewer (tree | editor |
  terminal), with the same session, output and running program. **Undock** sends it back to the bottom
  chat-like dock.
- The docked column resizes with the separator, minimizes to a rail (button, shortcut, or dragging the
  separator), shows an unread dot when output arrives while it's minimized, and restores at its previous width.
- The tree and the terminal can each be hidden independently. Reloading the page restores the tree width, the
  terminal width, which terminals are docked, and what's minimized.
- Several docked terminals show as tabs. Leaving the explorer and coming back keeps them docked. Narrow
  screens fall back to floating.
- A full-screen program (e.g. `htop`) keeps running and redraws correctly after dock/undock.
- e2e: dock, undock, minimize/restore, reload persistence, and dragging a tree row onto the docked terminal.
